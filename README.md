# Alvaro Cruz Perez — Engineering Portfolio

This version is intentionally **not tailored to one company or one job posting**.

The portfolio is organized around a professional story:

1. **Systems foundations** — learning sensor integration and disciplined troubleshooting.
2. **Mechanical ownership** — becoming Mechanical Lead on an electromechanical hand-assessment device.
3. **Research hardware** — designing and validating custom equipment in a constrained 7T MRI environment.
4. **Quantitative biomechanics** — adding Python, computer vision, and kinematic analysis to the toolkit.
5. **Leadership growth** — taking greater responsibility for team coordination while maintaining technical project ownership.

The goal is to make the portfolio useful for roles in:
- medical devices
- mechanical design
- biomechanics
- robotics
- R&D / research engineering
- electromechanical systems
- research instrumentation
- manufacturing / prototyping

## Publishing on GitHub Pages

Create the public repository:

`alvarocruz15.github.io`

Upload the **contents** of this folder to the repository root. `index.html` should be directly visible at the top level.

Then:
1. Go to **Settings > Pages**
2. Choose **Deploy from a branch**
3. Select `main`
4. Select `/ (root)`
5. Save

The site should appear at:

`https://alvarocruz15.github.io`

## Add visuals before using it heavily in applications

The current pages are text-first because the portfolio should not guess what material is cleared for public release.

For each project, add 2–5 approved visuals that show a progression:
- problem / context
- early concept
- CAD or schematic
- prototype
- test setup
- result / lesson

### Important
- **MACRO:** do not publish NDA-covered content.
- **Research:** confirm with your PI/lab before posting unpublished data, animal images, internal setups, or technical details.
- Avoid confidential dimensions, drawings, files, or source data.

## Recommended visual strategy

### Wearable
Use a block diagram, PCB/prototype photo, sensor layout, or a simple troubleshooting flow.

### MACRO
Use only cleared visuals. A high-level system view, sanitized CAD render, or non-confidential prototype image is ideal.

### MRI cradle
Use an approved CAD render, prototype image, attachment-mechanism detail, or simplified design-constraint graphic.

### Gait analysis
Use an approved video frame with pose overlay, workflow diagram, kinematic plot, or a generic/sample output.

## Keep the portfolio broad

Do not rewrite it for every application. Instead:
- tailor the **resume and cover letter** to the job
- keep the **portfolio** stable as the deeper story of your development
- reorder or feature projects only when you eventually have enough material to justify it

The homepage should answer:
**Who is Alvaro becoming as an engineer?**

Each project page should answer:
**What did this project teach him that changed the next one?**
